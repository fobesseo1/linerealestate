## 직접 등록

메일 발송 제한으로 첫 비밀번호 설정을 진행하지 못하는 경우, 이 컴퓨터에서 `scripts/set-admin-password.ps1`을 실행한다. 로컬 창에 사용자가 비밀번호와 확인을 직접 입력하면 기존 두 관리자 계정의 비밀번호를 같은 값으로 설정하고 이메일 확인 상태를 처리한 뒤 실제 비밀번호 로그인·관리 권한을 검증한다. 다른 사이트와 같은 Auth 계정을 쓰므로 같은 이메일의 경매 비밀번호도 변경된다. Secret은 로컬 `.env.local`에서만 읽고 입력한 비밀번호는 프로세스의 표준 입력으로만 전달하며 파일·명령행 인수·로그에 기록하지 않는다. 에이전트가 비밀번호를 임의로 정하거나 입력하지 않는다.

1. 이메일·비밀번호로 로그인한다. ‘이메일 기억하기’는 이메일만 저장하고, 비밀번호는 브라우저의 비밀번호 관리자·자동 완성을 사용한다. 로그인 세션은 유지된다. 처음이거나 비밀번호를 잊었다면 ‘비밀번호 처음 설정 / 비밀번호를 잊으셨나요?’ → 설정 메일 받기 → 메일의 로그인 버튼 → 새 비밀번호·확인 입력 → 저장하고 시작하기 순서다. 링크를 붙여 넣는 과정은 기본 흐름에서 필요하지 않다. 두 사이트는 Supabase Auth 계정을 공유하므로 같은 이메일의 비밀번호를 설정하면 경매 사이트에도 같은 비밀번호가 적용된다.
2. ‘새 등록’에서 분류를 고르고 사진·짧은 메모부터 작성한다. 모든 필드는 초안 저장 시 비워둘 수 있다. 빈 금액은 0원이 아니라 미확인이다.
3. ‘초안 저장’을 누르면 `SUN-1001` 형태의 매물번호가 발급된다. 사진은 최대 20장, 장당 15MB, JPG/PNG/WebP. 첫 사진이 대표 사진이며 앞·뒤 버튼으로 순서를 바꾼다.
4. ‘게시안 확인’은 수정안만 생성한다. 제목·분류·설명 외에는 비워둘 수 있다. 비교 화면의 ‘승인하고 게시’와 확인을 거쳐야 공개된다.
5. 공개 숨김은 목록과 상세에서 자료를 숨기며 원본은 유지한다. 거래 완료는 표시만 변경한다. 이미 승인해 공개된 사진 URL은 공개 자산이므로 숨김을 파일 접근 철회로 보장하지 않는다.

## 이 채팅에서 보정

관리자 화면의 ‘보정 요청 복사’ 문장을 채팅에 붙여 넣거나 매물번호를 전달한다. 에이전트는 아래 로컬 명령으로 자료를 조회한다.

```powershell
node scripts/admin-content.mjs export SUN-1001
```

`.tmp/content/SUN-1001/original.json`과 등록된 WebP 사진을 작업용 비공개 로컬 폴더로 가져온다. 이 폴더는 Git·공개 배포에서 제외한다. 설명 수정안은 별도 JSON에 작성하고 보정 사진은 별도 파일로 만든다. 사진의 `localFile`을 작업 파일 경로로 바꾸면 긴 변 1200px · WebP로 변환하여 저장한다. 변환 전 사진 원본은 새로 저장하지 않는다. 사진은 실제 공간·구조를 바꾸지 않는 밝기·색감·수평 보정만 한다. 이미지 작업은 imagegen 스킬을 읽고 수행한다. 확인되지 않은 거래 조건을 추측해 채우지 않는다.

```powershell
node scripts/admin-content.mjs revise SUN-1001 .tmp/content/SUN-1001/revised.json
```

이 명령은 승인 대기 수정안만 저장한다. 번호와 원본 버전이 맞지 않으면 거부한다. 공개할 주소는 Naver Geocoding으로 번지 일치를 검증해 좌표를 추가하고, 검증 불가 시 지도 검색 링크로 안내한다. 관리자 화면에서 새로고침 후 비교·승인할 수 있다.

관리자 화면으로 등록하는 경우에도 주소 공개·지도 표시를 선택하면 초안 저장과 게시안 생성 시 사이트 서버가 네이버 주소를 확인해 좌표를 자동 저장한다. 비밀 키를 다른 GPT나 브라우저에 전달할 필요가 없다. 주소를 바꾸면 이전 좌표는 재사용하지 않는다. 임시 초안은 위치 확인이 실패해도 보관하지만, 지도 좌표가 없는 게시안은 공개하지 않는다. 이전 게시안에 좌표가 없다면 입력창에서 ‘게시안 확인’을 다시 눌러 새로 준비한다. 다른 GPT는 관리자 화면으로 등록·게시한 뒤 공개 상세에서 지도와 핀을 확인한다.

**2026-10-12 사용자가 이 채팅에서 사진·내용 추가 또는 수정 요청 자체를 공개 승인으로 처리하도록 명시적으로 지시했다.** 요청 범위의 사진·내용을 별도 수정안으로 준비하고 검증한 뒤, 에이전트가 아래 명령으로 승인·게시까지 완료한다. 추가 승인 질문을 반복하지 않는다. 미리보기·초안만 요청하거나 공개하지 말라고 한 경우에는 게시하지 않는다. 이 승인은 요청한 콘텐츠 변경에 한정된다. 관리자 화면에서 직접 입력한 자료는 기존 비교·승인 절차를 유지한다.

```powershell
node scripts/admin-content.mjs publish REVISION_UUID --human-approved
```

에이전트는 위 사용자 승인 범위에서만 게시한다. 해당 명령은 로컬 Secret을 사용하므로 GitHub Actions나 브라우저에서 실행하지 않는다. 서버 Secret과 관리자 세션을 출력하지 않는다. 비공개 메모·소유자 연락처는 공개 스냅샷에서 제외한다. 기본적으로 정확한 주소도 비공개이며, ‘정확한 주소 공개’를 선택한 자료만 주소·지도 정보를 공개한다.

## 저장 구조

Supabase Authentication → URL Configuration에 `https://fobesseo1.github.io/linerealestate/admin/**`, `http://localhost:3010/admin/**`를 추가했다. 기존 경매 Site URL은 유지한다. 설정 메일은 `emailRedirectTo`로 선부동산 `/admin/?flow=setup`을 지정한다. 복귀 시 인증 정보를 처리하고 주소에서 제거한 뒤 허용된 관리자만 비밀번호 설정 화면을 표시한다. 잘못된 주소로 갔던 예전 메일은 기본 로그인에서 ‘비밀번호 처음 설정’을 눌러 새 메일을 받는다.

- `lineestate_admins`: 관리자가 허용한 이메일 목록. 로그인 사용자는 자신의 권한만 조회.
- `lineestate_drafts`: 입력 초안과 비공개 메모. 관리자만 조회·수정.
- `lineestate_revisions`: 원본·보정안·원본 버전·승인 상태. 관리자만 조회·수정.
- `lineestate_published`: 승인한 공개 자료만 포함. 방문객은 active/completed 자료만 조회.
- `lineestate-originals`: 초안·수정 이력용 1200px WebP 저장소(기존 이름 유지). 관리자용 URL은 1시간 유효.
- `lineestate-public`: 승인 시 복사한 공개 사진.

공개 사이트는 저장소에서 승인 자료를 읽으므로 등록 때마다 Git 재배포가 필요하지 않다. 중개 사례는 기존 4개를 포함해 모두 lineestate 데이터 저장소에서 조회한다. 관리자에서 내용·사진 수정 후 승인하면 홈·사례 목록·상세에 반영되고 Git·Vercel 재배포는 필요 없다. 기존 #work/pyeonbaek·salon·comma·clinic 주소는 lib/content/legacy-work-routes.json의 매물번호로 연결한다. 이 파일은 주소 연결 정보만 담고 사례 내용을 담지 않는다. 사례 내용을 lib/real-cases.json 또는 프런트엔드 코드에서 수정하지 않는다. 원본 사진은 추가 보관하지 않고 관리자 업로드는 lib/content/photo.ts, 채팅·이전은 lib/content/photo-node.mjs를 통해 긴 변 정확히 1200px의 WebP만 저장한다. 기존 역사 원본 삭제는 사용자에게 범위 승인을 받은 뒤에만 수행한다.
